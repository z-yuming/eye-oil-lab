## 一、项目背景

用户在另一台电脑上已经围绕“AI 产品开发全流程平台”完成了一轮规划，并带来了市场调研、竞品、人群、包材、成品和代加工供应商等真实业务资料。当前工作以“眼油产品”作为第一个演示和落地品类，用真实产品开发数据验证工作台是否有用。

平台的核心目标不是把所有工作强行串成一条漫长流程，而是把产品开发拆成可并行推进、可随时回看的工作流：

- 前期能够根据市场机会、用户痛点和竞品快速形成自己的产品路径。
- 中后期能够把产品概念落到配方、包材、包装、供应商、打样和验证。
- 每个正式立项的产品都有独立项目记录，不会被后续项目覆盖。
- 关键判断、证据、供应商状态和验证结论可以持续追溯。

## 二、对话中的关键决策

### 1. 以眼油产品作为首个工作样本

产品方向暂定为眼部护理场景下的滚珠眼油/眼部精华油。首个项目用于验证：市场机会判断、竞品拆解、目标人群、概念方案、定位、包装、工厂落地和产品效果是否能够在同一个工作台中协同。

### 2. 供应商匹配需要从“展示名单”升级为“按物料匹配”

供应商部分不能只显示供应商名称，而要按实际采购对象拆开：

- 包材：瓶器、滚珠头、内塞、外盖等。
- 内料：配方、原料、肤感和打样能力。
- 包装：纸盒、说明书、标签、印刷和后加工。
- 代加工：配方开发、打样、灌装、检测和量产。
- 成品供应：适合快速验证或直接采购的成品方案。

匹配时需要同时考虑能力、MOQ、报价、打样周期、大货周期、地区、历史表现和待核验风险。供应商表中的信息只能作为原始业务资料，不能直接等同于已经验证完成。

### 3. 产品周期改为并行工作流

用户指出整个产品周期很长，不适合把所有阶段严格串联。因此平台采用“项目总览 + 八个并行工作流”的方式：

1. 市场调研分析
2. 人群分析
3. 竞品分析
4. 产品功能概念策划
5. 产品定位
6. 包装设计
7. 落地工厂与供应商匹配
8. 产品效果与上市准备

阶段仍然有完成状态，但团队可以从任意工作流进入；前期机会快跑和后期长期执行被拆开，既保持快速决策，也保留长期项目管理。

### 4. 前期需要“机会快跑”，后期需要“正式立项”

机会快跑用于快速比较市场机会、竞品空档和产品路径。只有选定可执行的产品方向后，才正式建立独立开发项目。

正式立项时需要保留：

- 来源机会
- 选定产品路径
- 初始决策记录
- 核心假设
- 第一批验证重点

之后的阶段执行不能悄悄覆盖初始基线，重要变化应留下新的决策记录。

### 5. 项目执行需要按项目留档

每个产品项目独立保存以下内容：

- 项目名称、项目编号和创建时间
- 来源市场机会与产品路径
- 当前阶段和完成进度
- 市场证据与机会判断
- 概念、定位、包装和供应商选择
- 阶段备注、风险和验证结论
- 关键决策记录

项目之间可以切换，切换后项目总览和阶段数据同步切换。

## 三、当前工作台已经完成的功能

### 产品机会快跑

- 查看市场趋势、用户痛点和竞品信息。
- 比较不同产品路径。
- 记录机会判断和关键决策。
- 从选定方向正式建立开发项目。

### 项目执行总览

- 显示当前项目、项目基线和完成进度。
- 以并行工作流卡片进入八个研发环节。
- 展示机会证据、供应商库规模和当前协同门。
- 提供项目方案导出入口。

### 项目记录

- 按项目保存独立快照。
- 查看开发中和已完成项目。
- 显示阶段进度、供应商匹配数和决策条数。
- 可以重新打开历史项目继续推进。

### 供应商匹配

- 接入包材、代加工和成品供应商数据。
- 支持按项目物料需求匹配供应商。
- 保留供应商来源、适配能力、MOQ、报价、交期和待核验状态。
- 支持供应商库导入和项目内自动保存。

### 本地保存与导出

- 当前项目状态自动保存到本机浏览器。
- 已有 JSON 项目方案导出能力。
- 本文件新增为项目上下文的 Markdown 记录。
